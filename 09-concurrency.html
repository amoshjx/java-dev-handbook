09 并发编程

线程、锁与线程池——正确性优先于性能，性能靠度量而非猜测。

1. 线程基础与生命周期（The Fundamentals）

并发编程的起点是“如何创建和控制线程”。在工程实践中，线程不是越多越好，而是要在资源上限内建立可控的并发模型。

1.1 创建线程的四种方式

  • 继承 Thread 类：简单直接，但不利于业务逻辑复用。
  • 实现 Runnable 接口：任务与线程分离，工程中更常用。
  • 实现 Callable 接口：支持返回值和异常传播，配合 Future 使用。
  • 线程池（最推荐）：复用线程、统一管理、支持监控与限流。

1.2 线程生命周期与状态切换

Java 线程包含 6 种状态：NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED。理解状态切换是排查线程问题（阻塞、死锁、长等待）的基本功。

stateDiagram-v2
    [*] --> NEW
    NEW --> RUNNABLE: "start"
    RUNNABLE --> BLOCKED: "等待监视器锁"
    RUNNABLE --> WAITING: "wait/join"
    RUNNABLE --> TIMED_WAITING: "sleep/timeout"
    BLOCKED --> RUNNABLE: "获得锁"
    WAITING --> RUNNABLE: "notify/interrupt"
    TIMED_WAITING --> RUNNABLE: "超时/interrupt"
    RUNNABLE --> TERMINATED: "run 结束"

图：Java 线程状态机

1.3 常用控制方法

  • start()：启动线程并进入就绪队列。
  • sleep()：当前线程休眠一段时间，进入 TIMED_WAITING。
  • wait() / notify()：对象监视器等待与唤醒，必须在同步块中使用。
  • join()：等待目标线程执行完成。
  • yield()：提示调度器让出 CPU，不保证立即生效。

1.4 参考实现：中断驱动的优雅退出

public void runLoop() {
    while (!Thread.currentThread().isInterrupted()) {
        try {
            Task task = queue.take();
            process(task);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            break;
        }
    }
}

2. 线程安全与并发三大特性（Core Principles）

多个线程同时访问共享变量时，若缺乏同步约束，就会产生线程安全问题。要保证正确性，必须理解并落实原子性、可见性、有序性这三大特性。

2.1 原子性（Atomicity）

一个或多个操作要么全部完成，要么全部不执行。像 i++ 这类复合操作在并发下不是原子的。

  • 解决手段：synchronized、Lock、原子类（如 AtomicInteger）。

2.2 可见性（Visibility）

一个线程修改共享变量后，其他线程必须能够及时看到最新值。由于 CPU 高速缓存与工作内存机制，可见性不会天然成立。

  • 解决手段：volatile、synchronized、Lock。

2.3 有序性（Ordering）

程序执行不总是严格按代码顺序进行。编译器和处理器会做指令重排以优化性能，因此并发下需要借助内存模型规则限制重排影响。

  • 解决手段：volatile（内存屏障）与 Happens-Before 原则。

3. 锁与同步机制（Locking & Synchronization）

为了实现并发三大特性，Java 提供了从关键字锁到 JUC 显式锁的一整套机制。选型原则是：先保证正确性，再通过压测做性能优化。

3.1 关键字锁

synchronized 是 Java 内置锁，可修饰方法或代码块。它在 Java 1.6 后有偏向锁、轻量级锁、重量级锁等升级优化。volatile 是轻量级同步机制，只保证可见性和有序性，不保证原子性。

3.2 JUC 显式锁

  • ReentrantLock（可重入锁）：支持公平/非公平、可中断等待、超时获取锁。
  • ReentrantReadWriteLock（读写锁）：读读共享，读写互斥，写写互斥，适合读多写少。
  • StampedLock（邮戳锁）：支持乐观读，读场景吞吐通常更高。

3.3 Happens-Before 关键规则

flowchart LR
    W1[volatile 写] -->|happens-before| R1[volatile 读]
    UNLOCK[synchronized 解锁] -->|happens-before| LOCK[synchronized 加锁]
    START[Thread.start] -->|happens-before| RUN[线程内动作]
    JOIN[线程结束] -->|happens-before| RET[join 返回]

4. JUC 工具包与高级并发组件（Advanced Toolkits）

java.util.concurrent（JUC）是 Java 并发编程的核心工具箱，覆盖线程调度、并发容器、同步器和无锁并发等关键能力。

4.1 线程池（Executor Framework）

线程池用于避免频繁创建和销毁线程带来的高开销。核心实现类是 ThreadPoolExecutor。

核心 7 大参数：核心线程数、最大线程数、空闲线程存活时间、时间单位、工作队列（WorkQueue）、线程工厂、拒绝策略（如 AbortPolicy、CallerRunsPolicy）。

flowchart TD
    TASK[新任务] --> CORE{核心线程未满?}
    CORE -->|是| EXEC1[核心线程执行]
    CORE -->|否| QUEUE{队列未满?}
    QUEUE -->|是| ENQ[入队等待]
    QUEUE -->|否| MAX{未达 max?}
    MAX -->|是| EXEC2[扩展线程执行]
    MAX -->|否| REJECT[拒绝策略]

图：ThreadPoolExecutor 任务提交流程

参考配置：生产可控线程池

int cores = Runtime.getRuntime().availableProcessors();
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    cores,
    cores * 2,
    60L,
    TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(1000),
    Executors.defaultThreadFactory(),
    new ThreadPoolExecutor.CallerRunsPolicy()
);

4.2 并发容器（Concurrent Collections）

  • ConcurrentHashMap：高并发下的首选 Map，Java 8 典型实现思路为 CAS + synchronized + 红黑树。
  • CopyOnWriteArrayList：写时复制，适合读多写少场景。
  • ArrayBlockingQueue / LinkedBlockingQueue：阻塞队列，生产者-消费者模型基础组件。

4.3 同步工具类（Synchronizers）

  • CountDownLatch：一个或多个线程等待其他线程完成后再继续，只能使用一次。
  • CyclicBarrier：多个线程互相等待到达同一同步点，可循环复用。
  • Semaphore：控制同一时间访问资源的线程数量，常用于限流。

4.4 原子类与无锁并发（Atomic & CAS）

CAS（Compare And Swap，比较并交换）是无锁并发的基础。常见类包括 AtomicInteger、AtomicReference，以及高并发计数性能更优的 LongAdder。

Semaphore permits = new Semaphore(50);
LongAdder successCounter = new LongAdder();

public void invokeDownstream() throws InterruptedException {
    permits.acquire();
    try {
        client.invoke();
        successCounter.increment();
    } finally {
        permits.release();
    }
}

5. 补充：现代 Java 并发新发展

虚拟线程（Virtual Threads / Project Loom）

在 Java 21+ 中，虚拟线程是并发模型的重要演进。它是极轻量的用户态线程，能够以更低成本创建海量并发任务，显著降低“一个 Java 线程对应一个操作系统线程”带来的资源压力。

对于高并发阻塞 IO 场景，虚拟线程通常比传统平台线程更易扩展；但 CPU 密集任务依然应以线程池并发度控制为主。工程上仍要保留超时、隔离、熔断、监控等治理能力，避免“线程变轻了就忽略容量边界”。

try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (Order order : orders) {
        executor.submit(() -> notifyPartner(order));
    }
}

验收标准：线程安全可证明、峰值下可降级、故障可观测、恢复路径可执行。

反模式预警

  • 把 volatile 当作“万能线程安全方案”，导致复合操作出现竞态。
  • 线程池使用无界队列或默认参数，流量峰值时内存和延迟失控。
  • 并发问题只靠线上日志排查，缺乏压测、线程转储和指标联动。
