10 IO·NIO·网络

文件读写、零拷贝与 HTTP 通信——后端日常接触最多的系统边界。

经典 IO

字节流、字符流与 try-with-resources

讲解

字节流（InputStream/OutputStream）处理二进制；字符流（Reader/Writer）处理文本并涉及编码。缓冲流（Buffered*）减少系统调用。Java 7+ try-with-resources 自动关闭实现了 AutoCloseable 的资源，避免泄漏。

flowchart TB
    subgraph BIO["BIO 阻塞 IO"]
      T1[线程1] --> C1[连接1 阻塞读写]
      T2[线程2] --> C2[连接2 阻塞读写]
    end
    subgraph NIO["NIO 多路复用"]
      SEL[Selector 单线程] --> CH1[Channel 1]
      SEL --> CH2[Channel 2]
      SEL --> CH3[Channel N]
    end

图：BIO 一连接一线程 vs NIO Selector 多路复用

示例代码

// 读文本文件
Path path = Path.of("config/app.yaml");
String content = Files.readString(path, StandardCharsets.UTF_8);

// 写 JSON
try (var out = Files.newOutputStream(path)) {
    mapper.writeValue(out, config);
}

// 大文件复制
Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING);

易错点

  • 未指定 Charset 用平台默认编码，跨环境乱码。
  • 手动 close 在异常路径跳过——用 try-with-resources。

NIO Buffer/Channel

Buffer 状态机与 FileChannel 零拷贝

讲解

Buffer 三属性：capacity、position、limit；flip() 将写模式切到读模式，clear()/compact() 用于重置或保留未读数据。FileChannel transferTo/transferFrom 在满足平台与通道条件时可利用内核态数据传输路径（常见为 sendfile）减少用户态拷贝与上下文切换。Selector 实现单线程多路复用，Netty 底层基于此。

flowchart LR
    REG[Channel 注册] --> SEL[Selector.select]
    SEL --> READY{就绪事件?}
    READY -->|OP_READ| READ[读 Buffer]
    READY -->|OP_WRITE| WRITE[写 Buffer]
    READ --> FLIP[buffer.flip]
    FLIP --> PROC[业务处理]
    PROC --> CLEAR[buffer.clear]

图：NIO Selector 事件循环流程

示例代码

try (FileChannel in = FileChannel.open(src, StandardOpenOption.READ);
     FileChannel out = FileChannel.open(dst,
         StandardOpenOption.CREATE, StandardOpenOption.WRITE)) {
    long transferred = 0;
    long size = in.size();
    while (transferred < size) {
        transferred += in.transferTo(transferred, size - transferred, out);
    }
}

关键/技巧

  • DirectByteBuffer 可减少堆内到堆外拷贝，适合高吞吐网络 IO；注意直接内存占用与 -XX:MaxDirectMemorySize。
  • 日常文件操作用 java.nio.file.Files API 即可，不必手写 Buffer。

HTTP Client

java.net.http.HttpClient（JDK 11+）

讲解

标准库 HttpClient 支持 HTTP/2、异步与连接复用。Spring RestClient/WebClient 是更高层封装。生产环境需明确配置连接超时（connect timeout）与请求超时（request timeout），并设计重试策略（仅对幂等请求）、并发/连接上限，以及配合熔断器（Resilience4j）。

示例代码

HttpClient client = HttpClient.newBuilder()
    .connectTimeout(Duration.ofSeconds(3))
    .version(HttpClient.Version.HTTP_2)
    .build();

HttpRequest req = HttpRequest.newBuilder()
    .uri(URI.create("https://api.example.com/orders/" + id))
    .timeout(Duration.ofSeconds(5))
    .header("Accept", "application/json")
    .GET()
    .build();

HttpResponse<String> resp = client.send(req, BodyHandlers.ofString());
if (resp.statusCode() != 200) throw new DownstreamException(resp.statusCode());

易错点

  • 同步调用未设超时时，网络异常可能导致调用线程长时间阻塞。
  • 每次请求 new HttpClient 丢失连接池复用。

序列化

JSON / Protobuf 选型

讲解

服务间 REST 普遍使用 JSON（Jackson）；高性能内部 RPC（如 gRPC）常用 Protobuf。避免 Java 原生序列化（安全与兼容风险）。DTO 与领域模型分离；日期时间用 ISO-8601 或 epoch，并显式约定时区语义。

示例代码

// Jackson 全局配置（Spring Boot 自动注册）
@JsonInclude(JsonInclude.Include.NON_NULL)
public record OrderDto(String id, Instant createdAt, BigDecimal total) {}

ObjectMapper mapper = JsonMapper.builder()
    .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS)
    .addModule(new JavaTimeModule())
    .build();

关键/技巧

  • 大数字 ID 前端精度丢失——JSON 序列化为 String。
  • 版本演进：新增字段 optional，禁止改字段语义。

Resilience4j 容错

HttpClient 与下游调用的生产级防护

讲解

裸 HttpClient 调用须配超时、有限重试、熔断。Resilience4j 提供 CircuitBreaker、Retry、TimeLimiter、Bulkhead、RateLimiter。Spring Boot 3 用 resilience4j-spring-boot3 声明式注解；详细配置与 Spring 集成见第 12 章 Resilience4j。

HttpClient 组合示例

CircuitBreaker cb = CircuitBreaker.of("downstream", CircuitBreakerConfig.custom()
    .slidingWindowSize(20).failureRateThreshold(50f).build());
Retry retry = Retry.of("downstream", RetryConfig.custom().maxAttempts(3).build());

Supplier<HttpResponse<String>> call = () -> client.send(req, BodyHandlers.ofString());
HttpResponse<String> resp = Decorators.ofSupplier(call)
    .withCircuitBreaker(cb)
    .withRetry(retry)
    .withTimeout(Duration.ofSeconds(5))
    .get();

易错点

  • 对非幂等 POST 自动重试导致重复副作用——见第 03 章幂等性。
  • 熔断阈值未压测校准，误杀正常流量。

Netty 概览

EventLoop 与 Pipeline

讲解

Netty 基于 Reactor：Boss EventLoop 接受连接，Worker EventLoop 处理 IO。ChannelPipeline 链式 Handler 解码/编码/业务。Spring WebFlux、Redis/MQ 客户端、Dubbo 等底层常用 Netty。业务代码一般不需手写，但需理解「不要在 EventLoop 做阻塞调用」。

flowchart LR
    BOSS[Boss EventLoop] -->|accept| WORK[Worker EventLoop]
    WORK --> PIPE[ChannelPipeline]
    PIPE --> DEC[解码 Handler]
    DEC --> BIZ[业务 Handler]
    BIZ --> ENC[编码 Handler]

图：Netty Reactor 模型与 Pipeline 链

示例代码

// 反模式：在 Netty worker 线程阻塞 JDBC
channel.pipeline().addLast(new SimpleChannelInboundHandler<HttpObject>() {
    @Override
    protected void channelRead0(ChannelHandlerContext ctx, HttpObject msg) {
        // 错误：db.query() 阻塞 EventLoop
        // 正确：提交到业务线程池，完成后 ctx.writeAndFlush(response)
        businessExecutor.submit(() -> {
            var result = service.handle(msg);
            ctx.executor().execute(() -> ctx.writeAndFlush(result));
        });
    }
});

速记

「EventLoop 非阻塞；阻塞任务丢线程池；Pipeline 进解码出编码。」

IO网络落地清单

输入

  • 文件/网络交互模式与吞吐目标
  • 协议规范与序列化约束
  • 连接池与超时策略要求

输出

  • IO/NIO/异步模型选型说明
  • 连接管理与超时重试基线
  • 网络异常与限流降级策略

验收标准

  • 关键接口具备可验证的时延指标
  • 序列化协议兼容策略已定义
  • 网络故障可触发自动降级

失败信号

  • 阻塞 IO 用在高并发主路径
  • 连接泄漏缺乏监控与兜底
  • 异常重试放大雪崩效应
