06 Java基础语法

语法、类型系统与现代 Java 编码习惯——高级开发者仍需反复校准的基本功。

1) 核心概念与运行机制

Java 程序最小认知框架

总结概括

  • 关键字与标识符：关键字（保留字）不能作为标识符；标识符由字母、数字、下划线、美元符组成，不能以数字开头，命名应语义清晰。
  • 入口方法：JVM 启动入口是 public static void main(String[] args)，访问修饰符、静态性、返回值和参数签名需完整匹配。
  • 注释：// 用于单行，/* ... */ 用于多行，/** ... */ 用于文档注释（可生成 API 文档）。

2) 数据类型与变量

类型系统与变量规则

总结概括

  • 基本数据类型：byte、short、int、long、float、double、char、boolean。
  • 引用数据类型：主要包括 Class、Interface、Array。
  • 类型转换：自动类型提升是低精度向高精度；强制类型转换可能导致截断和精度风险，需要显式评估边界。
  • 变量与常量：变量分局部变量与成员变量；final 修饰后不可再次赋值，用于表达常量语义或不可变引用。

3) 运算符

表达式计算的基础工具集

总结概括

  • 算术运算：+ - * / % ++ --。
  • 关系运算：> < >= <= == !=。
  • 逻辑运算：&& || !。
  • 赋值与位运算：+= -= 以及位移 << >> >>>。
  • 三元运算符：条件 ? 结果1 : 结果2，用于简洁表达二选一分支。

4) 流程控制语句

分支与循环的控制范式

总结概括

  • 分支：if-else 与 switch-case，switch 可用于 String 与枚举类型。
  • 循环：for、while、do-while 覆盖不同迭代场景。
  • 循环控制：break 用于跳出循环，continue 用于跳过当前轮次。
  • 增强 for：for-each 用于集合与数组的顺序遍历，代码更简洁。

5) 数组与方法

结构化数据与可复用逻辑

总结概括

  • 数组声明与初始化：支持静态初始化与动态初始化两种方式。
  • 数组访问与内存：通过索引进行读写；数组对象在堆中连续存储，访问具有确定顺序。
  • 方法定义：由修饰符、返回值、方法名、参数列表与 return 语句组成。
  • 方法重载：同名方法可因参数个数、类型或顺序不同而共存。

6) 面向对象基础语法（核心）

对象建模的最低必备语法

总结概括

  • 类与对象：使用 class 定义模板，使用 new 创建对象实例。
  • 封装：通过访问修饰符控制可见性，结合 Getter/Setter 暴露受控访问。
  • 构造方法：包含无参和有参构造，常用 this 完成同类构造调用与成员区分。
  • 继承：通过 extends 复用父类能力，借助 super 调用父类构造或成员。
  • 多态：子类可 Override 父类方法，父类引用可指向子类对象以统一调用接口。

7) 集合框架（Collection/Map）

集合选型与复杂度意识

总结概括

  • List/Set/Map 基本分工：List 保序可重复，Set 去重，Map 键值映射。
  • 常用选型：默认优先 ArrayList 与 HashMap；需要插入顺序可选 LinkedHashSet/LinkedHashMap；需要排序可选 TreeSet/TreeMap。
  • 并发容器：高并发场景优先 ConcurrentHashMap，避免直接在多线程下使用普通 HashMap。
  • 不可变视图：对外返回集合建议使用 List.copyOf/Set.copyOf，减少内部状态被误修改的风险。

并发集合补充

  • 复合操作优先使用 computeIfAbsent、merge 等原子方法，避免「检查再写入」的 TOCTOU（check-then-act）竞态。
  • CopyOnWriteArrayList 适合读多写少（如监听器列表），写操作整体复制成本较高，不要用于热点写场景。
  • 需要弱一致迭代器和非阻塞读时优先 ConcurrentHashMap；它不支持 null key/value，配合 Optional 或哨兵值表达「不存在」。

易错点

  • 在 foreach 中执行 remove 触发 ConcurrentModificationException，应使用 Iterator.remove 或 removeIf。
  • Arrays.asList 返回固定长度列表，不能直接 add/remove。

8) 泛型（Generic）

类型安全与 API 边界表达

总结概括

  • 核心价值：泛型在编译期约束类型，减少强制转型和运行时类型错误。
  • PECS 原则：读多用 ? extends T（生产者），写多用 ? super T（消费者）。
  • 类型擦除认知：运行时通常拿不到具体泛型参数，不能直接 new T()。
  • 工程建议：避免原始类型 List list，逐步清理历史代码中的未参数化集合。

示例代码

public static <T> void copy(List<? extends T> src, List<? super T> dest) {
    for (T item : src) {
        dest.add(item);
    }
}

9) Stream API

Stream 常用操作速查

概要

  • 心智模型：Stream 是声明式管道，不修改源数据；结构为 source → intermediate（惰性）→ terminal（触发求值）。
  • 入口：日常从 list.stream() 或 Arrays.stream(arr) 开始；无终止操作时中间步骤不执行。
  • 中间操作：filter 筛选、map 一对一映射、flatMap 展开嵌套集合；sorted/distinct/limit 有状态，大数据集慎用。
  • 终止与聚合：toList()（Java 16+，不可变）、collect、reduce；findFirst/min/max 返回 Optional，用 orElse/map 衔接，勿裸 get()。
  • 并行流：parallelStream() 走公共 ForkJoinPool，仅适合大数据 + CPU 密集 + 无副作用；含 I/O 或 Web 请求时不要用。
flowchart LR
    S["source\nlist.stream()"] --> I1["filter / map / flatMap"]
    I1 --> I2["sorted / distinct / limit"]
    I2 --> T["terminal\ntoList / collect / reduce"]

图：Stream 管道三段式（惰性中间操作 + 单次终止）

示例代码

// filter → flatMap → map → distinct → sorted → limit → collect
List<String> topTags = posts.stream()
        .filter(p -> p.isPublished())
        .flatMap(p -> p.tags().stream())
        .map(String::toLowerCase)
        .distinct()
        .sorted()
        .limit(20)
        .toList();

// reduce 与 Optional
BigDecimal total = orders.stream()
        .map(Order::amount)
        .reduce(BigDecimal.ZERO, BigDecimal::add);
Optional<User> admin = users.stream()
        .filter(u -> "ADMIN".equals(u.role()))
        .findFirst();

// 数值流避免装箱
double avgQty = orders.stream()
        .mapToInt(Order::quantity)
        .average()
        .orElse(0d);

易错点

  • lambda 里 list.add/map.put——副作用；并行流下数据竞争，应改用 collect。
  • peek 仅调试用，勿写库或改对象；无终止操作或 count() 链路上可能被跳过。
  • 同一 Stream 只能终止一次；toList() 返回不可变列表。
  • 大集合 sorted/distinct 占 O(N) 内存；Top-N 优先考虑堆，能下推 SQL 就不要全量进内存。
  • parallelStream 共享 commonPool，阻塞 I/O 会拖慢全 JVM；小数据集并行反而更慢。

速记

  • 排序：Comparator.comparing(Employee::dept).thenComparing(Employee::salary)，数值用 comparingInt，勿写 a - b。
  • 链路超过 5 步或 lambda 复杂时拆变量/抽方法；常规业务 Stream 与 for 性能接近，热点再优化。

Collectors：toList / toMap / groupingBy

概要

  • toList：Java 16+ 优先 .toList()；需可变容器用 Collectors.toCollection(ArrayList::new)。
  • toMap：toMap(keyFn, valueFn, mergeFn)——key 可能重复时必须传 mergeFn，否则抛 Duplicate key；value 不可为 null。
  • groupingBy：按字段分组，下游可接 counting、mapping、reducing、averagingDouble 等做组内聚合。

示例代码

Map<Long, Employee> byId = employees.stream()
        .collect(Collectors.toMap(
            Employee::id, Function.identity(), (a, b) -> a));

Map<String, Double> avgByDept = employees.stream()
        .collect(Collectors.groupingBy(
            Employee::department,
            Collectors.averagingDouble(Employee::salary)));

Map<Long, BigDecimal> amountByCustomer = orders.stream()
        .collect(Collectors.groupingBy(
            Order::customerId,
            Collectors.reducing(BigDecimal.ZERO, Order::amount, BigDecimal::add)));

易错点

  • toMap 默认 HashMap 无序；需保序传 LinkedHashMap::new，需排序传 TreeMap::new。
  • 分组结果 value 可为 null；toMap 的 valueFn 不允许 null——这类场景用 groupingBy。
