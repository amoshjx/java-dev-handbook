14 RuoYi 框架

RuoYi（若依）是常见的 Java 企业后台管理系统与快速开发框架，适合用来快速搭建管理后台、权限系统、CRUD 页面、代码生成和基础运维能力。本章只做入门导读：先认识它能解决什么问题，再跳转官方文档完成安装、启动和深入学习。建议在掌握第 12 章 Spring Framework之后再阅读本章。

官方文档：https://doc.ruoyi.vip/

框架定位

RuoYi 是什么

讲解

RuoYi 是基于 Java / Spring Boot 生态的后台管理系统脚手架，预置登录认证、用户角色、菜单权限、系统配置、日志、定时任务和代码生成等企业后台常用能力。它的价值不是替代业务架构设计，而是把后台项目的大量重复基础设施先搭起来，让团队更快进入业务开发。

适用场景

  • 企业内部管理后台、运营平台、权限系统和报表维护页面。
  • 以 CRUD 为主、需要快速交付的业务模块。
  • 学习 Spring Boot 分层、权限、日志、代码生成等后台工程实践。

版本选型

先从官方文档和主线版本入手

讲解

RuoYi 生态存在单体版、前后端分离版、微服务版以及社区增强版。初学者建议先按官方文档跑通一个 demo，再根据团队技术栈、是否需要微服务、是否需要增强特性决定版本。多数管理后台不必一开始就选择复杂架构。

脚手架选型对比

RuoYi vs JeecgBoot vs 自研

讲解

| 维度       | RuoYi           | JeecgBoot        | 自研脚手架        |
|------------|-----------------|------------------|-------------------|
| 权限模型   | RBAC 菜单按钮   | RBAC + 数据权限  | 按域定制          |
| 代码生成   | 表→CRUD 强      | 在线表单+代码生成| 无/自建           |
| 云原生     | 单体/Cloud 版   | 微服务可选       | 完全自控          |
| 学习曲线   | 低，文档多      | 中，功能多       | 高，无现成文档    |
| 适用       | 标准后台 CRUD   | 低代码+报表需求  | 强定制/合规隔离   |

选型写 ADR，勿因「熟悉某脚手架」绑定长期架构。与第 03 章模块化单体对齐：脚手架只解决基础设施，业务边界仍按 DDD 划分。

技术栈与架构

典型组成

讲解

常见组合为 Spring Boot + Spring Security + MyBatis（或 MyBatis-Plus）+ Redis + MySQL，前端多为 Vue（RuoYi-Vue）或独立 API（RuoYi-Vue-Plus / Cloud）。与第 17 章安全开发、第 11 章持久化内容可对照学习。

项目结构

前后端分离时的目录约定

讲解

后端通常按 admin / system / common / framework 等模块划分；前端独立仓库维护 views、api、components。二次开发时优先在业务模块扩展，避免直接修改框架核心代码。

快速上手

环境准备与启动顺序

讲解

按第 05 章开发环境准备 JDK、Maven、MySQL、Redis，导入官方 SQL，配置 application.yml 后启动后端，再启动前端 dev server。首次登录使用官方默认账号，立即修改密码并关闭演示环境的外网暴露。

权限能力（RBAC）

用户 · 角色 · 菜单 · 按钮

讲解

RuoYi 通过菜单树与权限标识（perms）控制页面与按钮可见性，后端使用 @PreAuthorize 等注解校验。与第 16 章 RBAC概念一致，可直接映射到企业权限模型。

代码生成

由表结构生成 CRUD

讲解

代码生成器根据数据库表生成 Entity、Mapper、Service、Controller 与前端页面，适合标准 CRUD 模块。生成代码需人工 Review，补充业务校验、事务边界与测试，避免直接上线未审查代码。若要为自有 Spring 多模块项目自建生成器，见第 15 章项目代码生成器。

系统能力

字典 · 参数 · 日志 · 定时任务

讲解

字典与参数配置支撑运行时可调整的业务枚举与开关；操作日志与登录日志满足审计需求；定时任务模块可对接 Quartz。与第 16 章常见功能模块中对应专题可交叉阅读。

前后端分工

联调与职责边界

讲解

前端负责交互与路由，后端提供 REST API 与权限校验。多租户（若启用）通常在数据层增加 tenant_id 过滤，需与业务表设计一并规划。

接口联调

统一响应与 Token

讲解

接口通常返回统一 JSON 包装（code/msg/data），登录后前端携带 Token 访问受保护资源。联调时对照 Swagger/官方接口文档，与第 03 章 API 契约实践保持一致。

二次开发

扩展规范

讲解

新业务放在独立业务包/模块，通过接口与框架层解耦；避免修改 ruoyi-common、ruoyi-framework 核心类。升级官方版本前备份自定义 diff，使用 Git 分支管理框架升级。

生产注意

安全与运维

讲解

生产环境必须修改默认口令、限制 Swagger/ Druid 暴露、启用 HTTPS、配置备份与监控。详见第 17 章安全开发与第 21 章 DevOps。

常见问题与排障

先查配置与权限链路

讲解

登录失败通常先检查数据库脚本、Redis、验证码与 Token 配置；页面无按钮或接口 403 先查菜单权限标识、角色授权和后端注解；生成代码异常先查表结构、包名、模块名和编码。细节排障以官方文档和项目日志为准。

学习 Checklist

从会用到理解原理

建议顺序

  • 按官方文档跑通 demo。
  • 体验用户/角色/菜单权限、代码生成、字典参数、日志和定时任务。
  • 结合本手册 Spring Boot、数据库、安全、常见模块章节理解实现原理。
  • 做真实业务前，先完成权限、数据范围、生产安全和业务边界评估。
